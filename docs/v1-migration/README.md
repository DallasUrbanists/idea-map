# Migration history

If you're looking into how Idea Map grew from its predecessor, start here.
This folder brings together source inventories, rights evidence, and capability
comparisons to help you investigate that history. These records are historical
context, not descriptions of the current application or its requirements.

The following contents links navigate within this guide:

- [Meaning and authority](#meaning-and-authority)
- [Contents](#contents)
- [Interpret the evidence](#interpret-the-evidence)

## Meaning and authority

Within this directory, **v1** means the predecessor
[`DallasUrbanists/improvement-map`](https://github.com/DallasUrbanists/improvement-map)
project, and **v2** means the
[`DallasUrbanists/idea-map`](https://github.com/DallasUrbanists/idea-map)
project containing this documentation. These terms describe project generations,
not package versions or proof of a deployed release.

You should not use these records to determine how v2 works today or what it
requires. Historical observations, issue mappings, and migration comparisons are
not current policy or guarantees of feature parity. For the project's
requirements, you can use the architecture, policies, and contributor guides
linked from the [documentation index](../README.md).

This directory is the exception to the rule that project documentation describes
the intended system in the present tense. Its evidence retains source revisions,
uncertainties, and historical descriptions. Project-generation terminology
belongs only here, apart from literal links and unrelated third-party version
identifiers.

## Interpret the evidence

When you use these records, you should distinguish committed source from
deployed behavior and verified permissions. A pinned revision or existing asset
does not establish deployment, provider approval, or a right to copy it.
Historical observations do not override the
[Terms of Use](../policies/terms-of-use-policy.md) or
[Privacy Policy](../policies/privacy-policy.md).
